# 求职方向：不只服务程序员

OfferCrew 一开始是给软件和 AI 工程师做的：判断岗位时，它默认你写代码，默认你在中国工作，默认「3 年经验」里包括实习。换成一位纽约大学今年毕业、学金融、拿着 F-1 OPT 找工作的学生，这几条默认全都不对。这份文档讲清楚现在系统怎么按「你的方向」来判断，以及它在哪些地方仍然保守。

## 1. 先认识几个词

- **方向**（direction）：你想做哪一类工作。现在有十二个：软件与 AI 工程、金融、法律、会计、咨询、市场、人力 / 行政、销售 / 商务、项目管理、产品、UI/UX 设计、运营、数据分析（2026-10-02 加了法律、会计、人力 / 行政、销售 / 商务、项目管理）。写在 `candidate/facts.yaml` 的 `preferences.directions`，第一个是主方向，后面的是「也看」。
- **细分**（track）：方向里面再分一层，写在 `preferences.tracks`。比如：
  - 金融：投行、研究、资管 / 投研、银行、风控 / 合规、量化、销售交易、财务 / 会计；
  - 法律：诉讼 / 仲裁、非诉、公司法务、合规、知识产权；
  - 会计：审计、公司会计、财务分析 / FP&A、税务、内审 / 内控；
  - 人力 / 行政、市场、销售 / 商务、项目管理也各有几条（见 `lib/directions.mjs`）。

  一个细分可以对应几个岗位类别。金融的「资管」同时对应资管和券商研究，所以以前选了资管的人，研究岗照旧算方向以内；法律的「知识产权」同时算律所执业和公司法务。
- **岗位类别**（family）：系统给每个岗位贴的标签，比如「投行」「资管 / 投研」「咨询」「软件工程」「销售 / 商务」。判断一个岗位对不对你的方向，就是看它的类别。
- **相邻**：和你的方向挨着、但不是你主攻的类别。比如你选了金融里的投行和资管，那么风控、量化、咨询、数据分析就是相邻的。相邻的岗位不会被提前筛掉，但系统不会直接推荐，会写一句「方向待核」让你决定。
- **预筛**：在花钱请模型读 JD 之前，先只看标题和几条硬规则，把明显不合适的岗位挡掉。挡掉的岗位都有一个看得懂的原因，比如「级别偏高」「方向不对」「你不做的岗位类型」。

## 2. 没写方向的人：一切照旧

`candidate/facts.yaml` 里没写 `preferences.directions` 的人，系统当成软件方向，走的是和以前一模一样的规则。作者本人就是这种情况。

为了保证「一模一样」不是一句空话，仓库里有一份金标准测试（`tests/golden-software.test.mjs`）。它在改动之前，把 138 个岗位分别配上 4 种虚构的软件方向候选人，完整跑了一遍判断，把每一步的结果都记了下来：预筛的原因、年限缺口、排序分、发给判断模型的每一个问题、最后的结论、申请表上填的每一栏、求职信的全文。之后每次改代码，这个测试都会重跑一遍，逐条对照，差一个字就会报错。另外，在本机把作者 2328 条真实岗位的副本也对照过一遍，结果是 0 处差别（这一步不进仓库，因为数据是私人的）。

## 3. 选了别的方向，哪些规则会变

下面用一个虚构的例子来讲：**苏示例**，2026 年 5 月从纽约大学金融专业本科毕业，做过一段投行暑期实习（Summer Analyst）和一段研究所实习，CFA 一级已过，中国公民，在美国用 F-1 OPT 工作。她的方向写的是金融，细分选了投行和资管。

### 3.1 实习怎么算年限

招聘里说的「2 年经验」，在金融和咨询行业指的是全职工作，实习不算。所以苏示例的「工作年限」是 0，而不是把两段实习加起来的半年。软件方向照旧把实习算进年限，这是软件行业的惯例，也是作者一直在用的算法。市场、运营、产品、数据分析这四个方向取中间：一段实习按一半算。

这个数字只影响两件事：一是 JD 写死的年限（比如「5 年以上」）会不会让岗位直接被筛掉；二是判断时会不会写出「年限缺口：JD 要求 2 年以上经验，候选人约 0 年全职经验（实习不算全职年限）」这样的提醒。实习本身仍然是最重要的证据，判断和求职信都会引用它。

如果你在 `experience_summary.years` 里明写了一个数字，系统就用你写的，不再推算。

### 3.2 级别词换成这个行业的说法

软件行业里，Staff 是资深的意思；会计行业里，Staff Accountant 却是入门岗。银行里的 Vice President（VP）是干了六七年的资深员工，不是公司副总裁。银行校招的「客户经理」「理财经理」是岗位名称，不是级别。

所以通用方向用的是另一套级别词：Senior、Lead、Principal、VP、Director、Manager、资深、高级、主管、经理、总监会被当成「偏高」；Analyst、Associate、Staff、专员、助理、管培生不会。像「客户经理」「产品经理」「总经理助理」这类岗位名，会先从标题里拿掉，再判断级别。

同一个词在不同行业里意思不一样，所以金融、会计、法律、销售还各有一张「行业职级表」：

| 方向 | 词 | 算哪一档 |
| --- | --- | --- |
| 会计 | 高级审计员、Audit Senior、S1–S3；内资所的审计项目经理 | 有经验（四大的 Senior 一般干了两三年） |
| 会计 | 审计经理、Audit Manager | 资深 |
| 法律 | 律师、Associate | 有经验（律所的 Associate 是执业律师） |
| 法律 | 资深律师、Senior Associate、律所的顾问（Counsel） | 资深 |
| 法律 | 律师助理、实习律师、Paralegal、Trainee Solicitor | 应届 |
| 金融 | 校招或项目制的 Analyst | 应届 |
| 金融 | Associate | 有经验 |
| 金融 | VP、副总裁 | 资深（银行的 VP 不是高管） |
| 销售 | 销售经理、客户经理、大客户经理、客户成功经理 | 有经验（多数不带人） |

这些例外也写进了给判断模型的级别说明里。另外，标题里出现这些职级时，系统会按一张粗略的表推一个「大概要几年」：投行 Analyst 0–3 年、Associate 3–6 年、VP 6 年以上；四大审计员 0–2 年、Senior 2–5 年、经理 5 年以上；律所资深律师 4 年以上 PQE。数字是公开说法的粗略归纳，仅供参考。差得太多（比你多 3 年以上）才在入库前挡掉，差一点就写成「职级缺口」，由你来定。只有主方向对得上时才用这张表。

### 3.3 应届生和实习岗

系统会根据你的教育经历推断你现在处在哪个阶段：还在读书、刚毕业（毕业不到 18 个月，而且全职不满 1 年），或者已经有工作经验。

刚毕业的人，写着「Analyst Program」「校招」「管培生」「2026 届」的岗位会排得更靠前。至于面向在校生的实习岗（Summer Analyst、暑期实习），只有两种情况会推给你：你还在读书，或者你在方向说明里写了「实习」。

招聘要求里常见「2025 年 12 月到 2026 年 6 月之间毕业」这样的时间窗口。系统会按月份比较你的毕业时间：2026 年 5 月毕业的人，不在「2026 年 12 月到 2027 年 6 月」这个窗口里。

**届别对不上的校招岗直接排除。** 还在读书或刚毕业的人，系统会看岗位的标题和正文写的是哪一届：

- 「2027届」「2027 届」「27届」「2027年应届毕业生」，都是 2027 届；
- 「毕业时间为 2026年8月至2027年7月」「2026.8-2027.7」，按月份比；
- 「Class of 2027」「graduating between December 2026 and June 2027」，也算 2027 届。

你的届别按毕业月份算，8 月起算下一届：2026 年 5 月毕业是 2026 届，2026 年 12 月毕业是 2027 届。对不上就排除，缺口写成「届别：岗位招 2027 届，你是 2026 届」。比如 10 月份的秋招板上，「【2027届秋招】财务审计助理」对 2026 届的人就是排除。

看不出届别的照常判断，下面这些都算看不出：

- 只写了实习年份，比如「2027 Summer Analyst」；
- 只写了一个毕业月份；
- 「2025届及以前」这类开口的写法；
- 同一句里还写了「或一至两年工作经验」。

实习岗也一样，「2028届实习」按届别比。已经有工作经验的人不做这条。

### 3.4 工作许可和签证

以前系统默认你是中国大陆公民，没有海外工作许可。现在它看 `work_authorization` 这一项：

- `china_mainland: citizen` 表示可以在中国工作。
- `us` 可以填 `citizen`（公民）、`permanent_resident`（绿卡）、`f1_opt`、`f1_stem_opt`、`h1b`、`needs_sponsorship`（需要担保）或 `none`（没有）。旧的自由文字照样认得。认不出的一律当成「没有美国工作许可」，这是以前的默认。比如作者写的是 `F1_expired`，意思是以前在美国读过书、现在没有工作许可，系统就按「没有」处理。

按这两项，系统会算出你能在哪些地方合法工作，然后做下面几件事：

- **远程岗位**：只要对你能工作的地区开放就行。比如「Remote - US」对苏示例是可以的，「Remote - EMEA」不行。
- **JD 里的签证说法**，由代码直接读，不靠模型猜：
  - 写明「现在和将来都不提供签证担保」（now or in the future）的岗位：她以后需要 H-1B，所以判为冲突，直接排除。
  - 只写了「需要无需担保就能工作」的岗位：她现在用 OPT 可以工作，但以后的事说不准，所以判为「待核」，缺口里写清楚这一点，由她自己决定。
  - 写明要求美国公民身份，或者要求安全许可（security clearance）的岗位：冲突。
- **申请表**：遇到「你现在或将来是否需要签证担保？」，拿 OPT 的人如实回答「需要」；如果问题只问「现在」，就回答「不需要」。问的是英国、加拿大这些别的国家时，系统不猜，停下来问你。美国的岗位按美元填期望薪资（`compensation.expected_annual_usd`）。没有通知期（notice period）的应届生，按最早入职时间填写，不会编一个「30 天」。

只能在中国工作的人，上面这些都不会出现：判断时问的是以前的原句，申请表也按以前的方式填。

### 3.5 证书

金融、会计、咨询、市场的招聘里，证书常常是一条硬要求：「CFA 二级及以上」「须持有基金从业资格」「CPA 优先」。系统按方向准备了一张常见证书表（在 `lib/certifications.mjs`）：

| 方向 | 常见证书 |
| --- | --- |
| 金融 | CFA、CPA / 注册会计师、US CPA、ACCA、FRM、CMA、CAIA、CFP、FINRA 执照（SIE / Series 7 / 63 / 79…）、证券从业、基金从业、期货从业、银行从业、法律职业资格、保荐代表人、证券投资顾问 / 证券分析师、香港证监会牌照（SFC / HKSI），语言证书 |
| 法律 | 法律职业资格（分 A / B / C 证）、律师执业证、专利代理师资格、境外律师资格（纽约州、英格兰及威尔士、香港）、证券从业、基金从业，语言证书 |
| 会计 | CPA（数通过几科）、US CPA、ACCA、CMA、税务师、会计职称（初 / 中 / 高级）、CIA、CISA、CFA，语言证书 |
| 人力 / 行政 | 企业人力资源管理师、经济师（人力资源）、SHRM、CIPD，语言证书 |
| 销售 / 商务 | 驾照 |
| 项目管理 | PMP、PRINCE2、软考信息系统项目管理师、建造师（二级 / 一级） |
| 咨询 | CPA、US CPA、CFA、ACCA、PMP、法律职业资格 |
| 市场 | Google Analytics、Google Ads、HubSpot、Meta Blueprint |
| 产品 | PMP、NPDP、CSPO |
| 数据分析 | Google Analytics、Tableau、CDA |
| 软件 | 没有这张表，规则和以前一样 |

你的证书写在 `certifications` 里，每条写名字和状态，比如 `{ name: CFA, status: Level I passed }`。系统会分清三种说法：「要求」「优先」「入职后取得」。只有同时满足下面三条，才会写成缺口，并把结论降到「待核」：

1. JD 要求这张证；
2. JD 没说可以入职后再考；
3. 你还没满足。

比如 JD 要求 CFA 二级及以上，而苏示例只过了一级，缺口会写成「证书：JD 要求 CFA 二级及以上（你：CFA Level I passed）」。如果你的资料里压根没写 `certifications` 这一项，缺口会写「你的资料里还没写证书，去补上」，而不会说你没有。

有些证书不只看「有没有」：

- **分档的**：会计职称初级 < 中级 < 高级，建造师二级 < 一级，日语 N2 < N1，英语四级 < 六级 < 专八，法考 C 证 < B 证 < A 证。JD 要某一档，你在这一档或以上就算满足：六级能满足「四级及以上」，专八能满足「六级」。JD 要 A 证而你是 C 证，缺口写「证书：JD 要求 法律职业资格 A 证（你：法律职业资格 C证）」。
- **数科目的**：「通过 CPA 2 科及以上」对「已通过 3 科」是满足。
- **中美 CPA**：JD 只写「CPA」时，中国 CPA 或 US CPA 有一个就算；写明「中国注册会计师」或「US CPA / AICPA」时，要对应的那一种。
- **考试成绩**：雅思、托福两边都读得出分数就比分数，读不出来只看有没有。

语言证书除了 `certifications`，也会从 `languages`、`standard_answers.languages` 和 `skills` 里读，比如你在技能里写了「英语六级」「IELTS 7.5」。

### 3.7 机构背景

JD **要求**「四大审计经验」「红圈所经验」时，系统会对照你的经历（`current_work.company` 和 `career_highlights` 里每段经历的公司）。没有的话写一句缺口，比如「背景：JD 要求四大审计经验（你的经历里没有）」，结论最多到「待核」。

- 名单是写死的：四大是德勤、普华永道、安永、毕马威；红圈所是金杜、方达、君合、中伦、通商、海问、竞天公诚、环球，以及它们的英文名。
- 写的是「优先」，或者「四大或大型内资所」这种有别的选项的，不算缺口。「四大行」说的是银行，不算。
- 名单不固定的说法（「头部券商」）照旧交给判断模型。

### 3.8 执业年限（法律方向）

律所说的年限是 PQE，也就是拿到执业资格以后的年数，不是毕业以后的年数。JD 写「3 年以上执业经验」「2–4 年 PQE」时，法律方向的人按律师执业证的日期来算：在 `certifications` 里写 `{ name: 律师执业证, status: 已取得, date: 2023-03 }`。

- 年数够，不写缺口；不够，写「年限：JD 要求 5 年执业经验，你约 3.5 年（按律师执业证日期算）」。
- 没写日期，写「年限：JD 要求 3 年执业经验，你的资料里没写执业证日期」，结论是待核。这时不再按工作年限另写一条年限缺口。

### 3.9 年龄、性别、婚育

「35 岁以下」「限男性」「已婚已育优先」这类要求不参与判断：不当成硬要求、不写缺口，也不会因为它排除或待核。JD 原文照常能看到。软件方向的判断和以前一样。

### 3.10 完全不在方向里的岗位

律所也招咖啡师、市场部的业务发展专员，这些岗位和律师方向毫无关系，系统直接排除，原因记成「方向不对」（`outside_target_specialty`），不再停在待核。

- 读 JD 时读出的类别既不在你的方向里，也不在相邻的方向里，入库前就排除。比如法律方向的人遇到市场岗、运营岗。
- 类别读成了「其他」、认不出是什么岗位的，看方向那一问：判断模型有七成把握说「不是你的方向」（`OTHER_FAMILY_DIRECTION_NO`，0.3），就排除，缺口写「方向不对：核心工作不在你的求职方向」。读出了方向以内的类别时，门槛照旧要七成五。
- 相邻的方向（法律看咨询，会计看税务）不因为方向排除，最多到待核，你来定。
- JD 太短、方向那一问答得模棱两可的，照旧是待核，不误伤。

### 3.6 求职信和申请表的用词

以前的英文求职信里写着「Professionally I have shipped production systems at…」，意思是「我在某某公司上线过生产系统」，这是程序员的说法。现在通用方向的求职信会：

- 写「我刚从某某大学毕业，获得某某学位」；
- 把实习写成实习，每段实习的要点各成一句；
- 证书、GPA、常用工具各有一句；
- 条款句按岗位所在国家写：在美国的岗位写美元，没写期望就写「可谈」。

只要资料够用，求职信照样凑到 150 词左右；实在不够，100 词以上也算合格，因为应届生的材料本来就少。

## 4. 找岗位的搜索词

有些国内招聘门户（北森、Moka、飞书招聘等）没有「列出全部岗位」的接口，只能按关键词搜。以前的搜索词是 AI、Agent、后端、全栈这一串，现在按方向换：

- 金融：投行、研究员、风控、财务、量化、管培生、分析师……
- 市场：市场、品牌、新媒体、投放……
- 法律：法务、律师、律师助理、法律顾问、合规、知识产权……

选了细分、而细分有自己的搜索词时，按细分搜：法律选了诉讼，就搜诉讼律师、争议解决、仲裁、律师助理。总助、秘书这类岗位搜「总经理助理」「部门助理」「行政助理」这些完整的叫法，不单独搜「助理」「秘书」，那样搜出来大多不是这类岗位。

岗位类别方面，2026-10-02 起把「人力 / 行政 / 法务」拆成了人力、行政、律所执业、公司法务四个，从「资管 / 投研」里分出了券商研究，从「财务 / 会计」里分出了审计和税务，从「销售 / 商务」里分出了拿提成的销售（保险代理、电话销售、理财 / 课程 / 置业顾问），另外加了商业银行和项目管理。已经判断过的岗位不重判，旧类别照常显示。拿提成的销售对谁都算「你不做的岗位」，选了销售方向也一样。

在你自己登录的浏览器里扫的帖子来源（LinkedIn 帖子、脉脉等，默认都关着）也是一样：搜索词换成你方向的词，按你的方向留帖子。这些来源只读你自己能看到的帖子，不打招呼，也不群发。BOSS 这类平台禁止自动化，我们不做批量打招呼。

### 4.1 引导卡片、渠道包和搜好的入口

「开始使用」第一步的卡片（`lib/presets.mjs`）从 5 张变成 12 张：原来的工程师、产品、数据分析、UI/UX 设计、运营在前，后面是金融、法律、会计、人力 / 行政、市场、销售 / 商务、项目管理。每张新卡片带上：

- 这个方向在注册表里的全部细分，默认身份是应届生，预算档是省钱；
- 公司包：金融、法律、会计各一份，另外四个方向共用一份「职能与管培」（`config/company-packs/business.example.yaml`）；文件还没建好时，引导页显示「还没有」；
- 渠道包 `config/channel-packs/<卡片>.example.json`；
- 简历提示和面试准备要点，按方向写，选了细分再多一两条；
- 面经去哪看：新卡片写自己方向常用的平台，工程师那几张卡片还是牛客、力扣讨论区、脉脉。2026-10-02 按调研核过一遍：牛客的会计面经少而旧；Wall Street Oasis 在更新，但要国际网络；脉脉、小红书、知乎的具体内容都核不到，其中小红书的间接证据很强；B 站上四大、快消的求职视频在更新。所以现在是：
  - 金融：牛客（银行、券商的公司面经页）、Wall Street Oasis（英文，要国际网络）、小红书；
  - 法律：小红书、知乎、B 站；
  - 会计：B 站（四大求职视频）、小红书、牛客（四大公司页，内容偏旧）；
  - 人力 / 行政：牛客（HR 校招面经）、小红书；
  - 市场：牛客（快消公司面经页）、小红书、B 站；
  - 销售 / 商务：牛客（快消公司页）、B 站、小红书；
  - 项目管理：B 站、知乎、小红书。

新方向的渠道包和技术方向有三处不同：

1. V2EX、电鸭、阮一峰周刊、Hacker News 是技术社区，这些方向的招聘帖很少，默认关。
2. 猎聘、智联、前程无忧、实习僧、国聘、LinkedIn 职位搜索，以及每个方向的垂直站（金融：eFinancialCareers、51 金融圈；会计：ACCA Careers、正保会计网校，上海、北京、广东三地注协的招聘栏目；法律：北京律协、深圳律协、上海律协（东方律师网）、Hughes-Castell；市场：数英网），条款或 robots.txt 都不许程序读。它们在包里是 `kind: manual`，**只放搜好的入口**：系统不读这些网站，只把链接按你的细分和目标城市填好，你自己点开看。
3. 有几个入口的地址带不了搜索词（`copy_keywords: true`），搜索词写在旁边给你复制：
   - 智联：搜索写法还没核对，先只放首页；
   - 51 金融圈、正保、律协、注协、Hughes-Castell：网站本身不能按关键词搜，入口打开列表页。各地律协、注协的列表页不按你的目标城市挑，都会列出来，名字里写着是哪个城市的。

LinkedIn 和 eFinancialCareers 从中国大陆网络直接打不开，入口旁边写着「需要能访问国际互联网」。

填链接的是 `lib/channel-entries.mjs` 的 `channelEntries(渠道包, 你的资料)`，它是纯函数，不读文件、不联网：

- **搜索词**：选了细分，就按细分的词轮流取。比如金融选了投行和研究，就是「投行、研究员、投资银行……」。没选细分，用每个来源自己的词。英文站用英文词。
- **城市**：取你的前两个目标城市。各平台的城市参数写在同一个文件的对照表里，只放核对过的：
  - 猎聘、BOSS：主要城市各有代码（10-03 复核），香港不带城市；
  - 前程无忧：主要城市和香港各有代码；
  - LinkedIn：北京、上海、香港用地区编号，深圳、广州、杭州用英文城市名；
  - 国聘：主要城市到市一级，其余到省一级；
  - eFinancialCareers、ACCA Careers、数英：几个主要城市。

  表里没有的城市不带城市参数，不猜代码。实习僧直接写中文城市名，哪个城市都行。
- **条数**：每个平台最多 3 条，例如「上海 投行」「北京 投行」「上海 研究员」。

入口在引导页和设置页里怎么显示，由引导页那边来接。

## 5. 没有模型也能看到判断：离线判断

判断岗位靠的是模型：判断层 Jev，或者文字模型。在演示 / 沙盒模式里，这两样都用不了，因为沙盒保证任何数据都不出这台电脑。为了让演示里也能看到「判断」这一步，系统有一个离线判断，打开方式是 `RADAR_JUDGE=offline`。它不联网，按规则回答判断层的同一套问题：

- 标题落在哪个类别；
- 学历、GPA、年限、毕业时间窗口满不满足；
- 你的经历和技能里有没有提到 JD 里的工具；
- 在不在你能工作的地方。

标题认不出类别时（「业务发展专员」「咖啡师」），离线判断会再看一眼正文。下面两种情况，它把岗位读成正文里最多的那个方向以外的类别，入库前按「方向不对」排除：

- 这个类别至少占 3 行，而且至少是碰上你方向那几行的两倍；
- 正文至少 3 行，一行都没碰上你的方向。

「碰上你的方向」指的是这一行里有你方向的类别词，或者这一行的常用词，比如法律方向的法律、合同、合规（`lib/directions.mjs` 的 `DIRECTION_DOMAIN`）。「……优先」「……为佳」的行不算；「金融市场」「资本市场」说的是行情，也不算市场营销。

它比模型笨得多。认不出的就答「不确定」，让结论停在「待核」，而不是编一个答案。它判出来的结论都标着 `judged_by: offline`，而且不会写进判断缓存，免得以后配了真模型还读到规则给的答案。

## 6. 沙盒里走到终审：只读的投递演示

真的投递要打开浏览器去填表，沙盒里不许打开浏览器。打开 `RADAR_APPLY=dry` 之后，投递这一步会：

1. 读 Greenhouse 公开招聘接口里这个岗位的申请表问题。这和嵌在公司官网上的表单是同一份，只读，也不用账号。
2. 用你的资料把能答的问题都答上；答不了的必填题，会停下来到收件箱问你。
3. 停在终审：你在收件箱里看到「系统打算怎么填」的每一栏。
4. 你点了「确认提交」之后，它也不会真的提交，只记一句「沙盒只演示到终审，没有真的提交」。

其他招聘系统（Workday、北森……）要登录，在沙盒里会交还给你，和没有浏览器的机器上一样。

## 7. 还比较保守、或者还没做的

- 离线判断只是演示和粗筛用的，真要投递，请配一个模型。
- 届别要等读过 JD、判断这一步才排除，入库前的标题预筛还不看届别，所以这些岗位会先进库，再被判成排除。
- 法律方向的「体制内」（考公、考编、法院和检察院系统）这次不覆盖，以后要不要做由负责人定。
- 校招和实习的读取（北森、Moka 等门户的校招 / 实习类别）、网申截止日期、测评和笔试步骤，由渠道那边在做，见 `docs/channels.md`。
- 缺证书时，收件箱里的「补资料」信还没做，要等中英文界面合进来之后再加。现在缺口已经会写在判断结果里。
- 质量规则（`config/quality-rules.json`）里的「可培养」「急聘」这几个排除词，对应届生可能太严了。它们是你可以直接改的配置，打开文件删掉就行。
