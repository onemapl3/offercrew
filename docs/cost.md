# 花了多少钱：token、估算和每天的上限

这一页讲三件事：token 是什么；「运行与用量」页上的钱是怎么估出来的；怎么给每天的花费设一个上限。管这些的是团队里的 System（后勤），这是它的「记账」技能。

## 1. token 是什么

模型不是按字数收钱，而是按 **token** 收钱。token 是模型读写文字时切出来的小块：

- 中文大约一个 token 是半个到一个汉字。「帮我看看这个岗位合不合适」十一个字，大约是 8 到 12 个 token。
- 英文大约一个 token 是四分之三个单词。

一次模型调用有两部分：

1. **输入**：交给模型读的东西。判断一个岗位时，输入是这个岗位的 JD 加上你的资料，常见是几千到一两万 token。
2. **输出**：模型写出来的东西，比如判断结论、一封信的草稿。输出通常比输入少得多，但单价贵好几倍。

### 命中缓存是什么

同一段内容被反复读时，模型服务商会认出「这段刚读过」，这部分输入叫 **命中缓存**，只按原价的一小部分收钱（常见是一成，有的更低）。

例子：执行器在一个会话里连做十件事，每做一步都要把前面的内容再读一遍。今天一次周期会话读了 1,039 万 token 的输入，其中 1,016 万是命中缓存的。所以页面上每一项都把输入拆成两块：**命中缓存** 和 **没命中**，没命中的那块才是贵的。

## 2. 钱是怎么估出来的

每次模型调用、每个执行器会话，System 都在本机记一行账（`state/usage.ndjson`）：哪位成员、为了哪件事、谁发起的、用的哪个供应商和模型、输入（命中缓存的和没命中的分开）、输出。

然后按价格表算钱：

```
钱 = 没命中的输入 × 输入单价 + 命中缓存的输入 × 缓存单价 + 输出 × 输出单价
```

单价都是 **每百万 token 多少钱**。举个例子：Claude Sonnet 5 的输入是 2 美元、缓存 0.2 美元、输出 10 美元。一次判断读了 1 万 token（其中 9 千命中缓存）、写了 500 token：

```
1,000 × 2 ÷ 1,000,000 + 9,000 × 0.2 ÷ 1,000,000 + 500 × 10 ÷ 1,000,000 = 0.0088 美元，约 6 分钱
```

几点要知道：

- **钱都是估算。** 价格表在 `config/prices.json`（第一次用时读仓库里的 `config/prices.example.json`），里面写着核对价格的日期和出处（Anthropic、OpenAI、DeepSeek、TypeSafe 的官方价格页）。价格会变，你的账单以供应商后台为准。页面上的人民币按价格表里的汇率折算。
- **订阅不算钱。** 用 Claude 订阅登录的 Claude Code、用 ChatGPT 订阅登录的 Codex，花的是订阅额度，不是按 token 付钱。页面上只写 token 和「订阅额度」，不编一个钱数。
- **额度还剩多少。** Codex 在自己的会话记录里写着「本周额度已用百分比」和重置时间，页面上照实显示，并写明是什么时候读到的。Claude 订阅的剩余额度在本机读不到，页面上就写「读不到」。
- **没定价的模型。** 价格表里没有的模型（比如你自己加的某个中转或本地模型）只记 token，页面上会点名。想让它也估钱，在 `config/prices.json` 的 `models` 里加一行：`"模型名": { "input": 输入单价, "cached": 缓存单价, "output": 输出单价 }`，单位是每百万 token 的美元；人民币标价的再加 `"currency": "CNY"`。
- **中转加价或打折。** 在价格表的 `providers` 里给那个供应商写 `"multiplier": 1.5`（贵一半）或 `0.5`（半价）。

### 执行器的账记在谁名下

执行器是大家共用的「手」，不是一位成员。它的每个会话，记到请它做事的成员名下：

- 收件箱巡检记给 Watcher；
- 公司调研记给 Judge；
- 即时执行按这一批任务是谁的活来记；
- 定时周期的大会话把几位成员的活放在一起做，先记给 System（定时运行是它的活），页面上写明原因。

System 只读 Codex 会话记录里的三样：启动目录（只算从 OfferCrew 目录启动的会话）、总用量、本周额度。对话内容一个字都不读、不存、不显示。会话记录默认在 `~/.codex`（设了 `CODEX_HOME` 就在那里）；在别的位置的话，在 `config/host.json` 里写 `"codex_homes": ["/那个/目录"]`。

### OfferCrew 补给

选「OfferCrew 补给」时，模型的钱由 OfferCrew 的中转付，你这边记的是 token：每次扣没命中缓存的输入 + 输出 + 命中缓存的输入 × 0.1（和价格的比例一致），用量页上写成「补给 12.3 万 · ¥0」。默认用 GPT-6 Astra；设置里可以给某位成员（比如 Watcher 读信）换成 GPT-6 Sol（更快、更省），两个都按用掉的 token 扣。

- 新用户试用 7 天，送 400 万 token，大约够一天判 120 个岗位、读信、对话，用满 7 天。没有「每天最多用多少」，送的就是这些。
- 导航栏有一格「⚡ 380 万 · 5 天」；「设置 → 模型与补给」和「运行与用量」也写着还剩多少、几天后到期。用量页每次操作一行：谁、做了什么、用了多少 token。
- 用完或到期以后，指挥台顶上会说「补给用完了」或「试用结束了」，新的判断和调研先停。换成自己的 API key 或这台电脑上的 Claude Code、Codex 就接着做。系统只换成你自己配过的模型，不会悄悄改用本机的 Codex。
- 中转为了防滥用有几条限制，比如每台电脑每天的调用次数。平时不显示，真碰上了才会说，北京时间第二天 0 点恢复，补给不会少。

## 3. 怎么设每天的上限

两个地方都能设：

1. 「设置 → 花费」（检查清单里的「花费档位与每天上限」也能点「选档位和上限」）；引导走完时，按你选的方向先记一个默认档位（你自己选过的不动）；
2. 「运行与用量」页下方的「上限和档位」。

可以设钱，也可以设 token，或者都设、都不设：

- **每天最多花多少钱**（估算的人民币）：适合用 API key 的人。比如填 10，今天估算到了 10 元就停。
- **每天最多用多少 token**：用订阅登录的也算在内，适合想控制订阅额度的人。

**都不设就是不限**，和以前完全一样。

### 到了上限会怎样

- **停下的**：判断新岗位、逐条匹配、一页评估、找联系人和内推人、自动排的公司调研、每天的真人帖扫描。这些线索和任务都留着，明天 0 点起自动接着做。
- **照常做的**：你已经批准的发信和投递、你自己点的调研、对话、读来信，还有执行器手上做到一半的事。上限从不打断你已经批准的事。
- 收件箱里会来一封信「今天的花费上限到了」，两个选择：
  - **今天再放宽 X**：只放宽今天（放宽的量是上限的一半），明天回到原来的上限；
  - **明天继续**：今天不再问你，明天自动接着做。

## 4. 三档花费

在同一个地方选：

- **省钱**：新线索先由你按标题挑一轮。收件箱里会来一封「按标题挑新线索」，一次 10 条，默认都留下，把不想要的改成「不要」。只有你留下的才花 token 去判断。你自己转发、收录来的岗位算你已经挑过。花得最少，只是多一件事要你点。
- **标准**：每条新线索都自动判断。和以前一样，也是默认的一档。
- **高级**：每条新线索都判断；推荐的岗位再写一页完整评估：级别、JD 自己写的薪资（没写就说没写，从不推算）、差距和对策、投递前值得先问清的事。逐条匹配和评估都用你配置里最好的模型。最贵。
