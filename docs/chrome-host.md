# 专用 Chrome：OfferCrew 自己操作的那个浏览器（2026-10-02）

## 一、它是什么

OfferCrew 有不少事要在网页上做：打开招聘网站的登录页交给你、检查你登没登录、扫要登录才能看的招聘来源、预填申请表。以前这些都要经过 ego（一个第三方的自动化浏览器），没装 ego 就做不了。

现在 OfferCrew 自己操作电脑上装的 Google Chrome，界面上叫**专用 Chrome**。几个要点：

- **用的是你电脑上的 Google Chrome。** OfferCrew 不打包浏览器，也不替你下载。没装 Chrome 时，它会说「这台电脑上没找到 Google Chrome」，并给出下载页 https://www.google.com/chrome/ ，由你自己去装。
- **它和你平时用的 Chrome 分开登录。** 专用 Chrome 用一份单独的「登录档案」（Chrome 存 cookie、登录状态的那个文件夹），放在数据目录的 `private/browser-profile`。你在这里登录 LinkedIn、字节跳动招聘，不会影响平时的 Chrome；OfferCrew 也读不到你平时那份档案。分开还有一个原因：新版 Chrome 不允许程序远程操控平时那份默认档案。
- **大家共用一个。** 登录检查、打开登录页、以后的扫描和预填，用的都是同一个专用 Chrome、同一份登录状态。你登录一次，处处都能用。

几个词：

- **调试端口**：Chrome 开着的一个本机网络端口，程序通过它告诉 Chrome「打开这一页」「读一下页面」。专用 Chrome 的调试端口只开在本机回环地址 127.0.0.1 上，端口号由系统随机分配。
- **状态文件**：`private/browser-host.json`，记着专用 Chrome 的进程号和端口号。只有你本人能读（权限 0600）。别的 OfferCrew 进程照它连上同一个 Chrome。
- **隐藏标签页**：后台的活（比如登录检查）开在一种不出现在标签栏里的标签页上，做完自动关掉，不弹窗口、不抢焦点，也不会碰你正在用的标签页。

## 二、它什么时候开、什么时候关

- **用到时才开。** 第一次要用浏览器的时候（比如你点「打开登录页」），OfferCrew 才把专用 Chrome 开起来。在 Mac 上它是另起的一个 Chrome 实例，你平时的 Chrome 开着也不影响；后台的活起它时不抢到最前面。
- **用着的时候一直开着。** 登录检查、扫描这些活接连来的时候不用每次重开。
- **闲着就关。** 10 分钟没用过、又没有给你看的标签页开着（你点「打开登录页」打开的那一页、交给你检查的页面、你自己在里面开的标签都算「给你看的」），OfferCrew 就把它关掉，运行日志里记一句「专用 Chrome 闲了 10 分钟，已关掉；要用时再打开」。登录状态存在档案目录里，关了不丢；只在这次打开期间有效的登录（有的网站把登录记在「会话 cookie」里）会跟着没了，下次检查会请你再登一次。
- **退出 OfferCrew 时一起关掉。**
- **你可以随时退出它。** 退出以后，OfferCrew 每分钟检查一次，发现它没了就记下来；下次真要用浏览器时再打开，不会马上又弹出来。
- **启动时加锁。** 两个进程同时要用浏览器，也只会开一个。

Mac 上要知道的一点：专用 Chrome 和平时的 Chrome 是同一个程序。平时的 Chrome 没开、只开着专用 Chrome 时，点程序坞里的 Chrome 图标，打开的是专用 Chrome（顶上有「Chrome 正受到自动测试软件的控制」的提示，书签和平时的不一样）。平时的 Chrome 也开着时，程序坞里会有两个 Chrome 图标。

## 三、不躲检测

专用 Chrome 就是一个正常启动的 Chrome，只多了专用档案和调试端口，外加标准的自动化开关 `--enable-automation`：

- 窗口顶上会显示「Chrome 正受到自动测试软件的控制」；
- 网页能看到 `navigator.webdriver` 是 true。

另外加了三个性能参数（`--disable-backgrounding-occluded-windows`、`--disable-renderer-backgrounding`、`--disable-background-timer-throttling`）：Chrome 平时会给后台的、被别的窗口挡住的页面降频，预填和扫描都在后台窗口里做，降了频就可能卡住；加上这三个就不用把窗口抢到你面前。Playwright 自己启动 Chrome 时也加这三个，它们和网站认不认得出自动化无关。

OfferCrew 不改浏览器指纹，不打隐身补丁，不伪装 webdriver，不去掉自动化标记。网站认出是程序在操作、拦下来、要你验证（验证码、安全检查）或者要你登录时，OfferCrew 就停下，把页面交给你，在收件箱里来信。

账号、密码、验证码只由你本人在专用 Chrome 里输入。OfferCrew 只负责打开登录页、检查你登好了没有。

## 四、打开登录页

收件箱的登录信、设置里的账号行上有「打开登录页」。点了以后：

1. 专用 Chrome 没开就先开；
2. 在「给你看的那个标签页」里打开登录页（一直复用这一个标签页，不会每次开一个新窗口），并把它拉到最前面；
3. 回执写「已在专用 Chrome 里打开」。网站返回错误时，页面照样交给你，你可以在里面刷新或换个地址。

## 五、登录检查：系统自己发现你登好了

每个账号的检查方法写在 `config/accounts.json` 的 `probe` 里。检查时，OfferCrew 在隐藏标签页里打开 `probe.url`，看落到了哪、页面上是什么：

- 被跳到了登录页（`logged_out_url`，比如地址里有 login、passport、sso），或者页面上有一整行「登录」「Sign in」（`logged_out_lines`）：**没登录**；
- 找到了只有登录后才有的东西：**登好了**。证据有两种写法：`logged_in_selector`（页面上的某个元素，比如你的头像）和 `logged_in_logout`（「退出登录」一类的按钮或链接，收在没展开的菜单里也算）；
- 配了证据却没找到，也没看到没登录的迹象：**看不出来**。不算没登录，你点「我登好了」照样能继续，只是系统不会自己替你判定；
- 碰到验证页（验证码、人机检查、访问太频繁）：**停下**，这个账号歇一阵再看（平时一小时，你刚点过「打开登录页」时两分钟），不去反复敲已经拦下来的网站。

什么时候检查：

- 有登录信在等的账号，每 10 分钟看一次；
- 你刚点过「打开登录页」的账号（收件箱的登录信、设置和收件箱的账号行都算，没有登录信在等也一样），接下来 10 分钟每 20 秒看一次。你在那个标签页里还停在登录页上时，这一轮先不看：还在登录的时候去开要登录的页面，有的网站（单点登录）会把你正在走的登录流程打断；
- 看到登好了，和你点「我登好了」完全一样：记下登录，挂着的任务继续，信自动消失。

招聘官网（字节跳动、腾讯、阿里、蚂蚁、网易、微软，以及北森的各家公司）的检查方法是 2026-10-02 在没登录的状态下实地看过定的：没登录时页面顶上都有一整行「登录」或「Sign in」。登录以后能看到什么还没有在真的登录状态下核对过，所以这些检查都标着 `"confirmed": false`：系统照样去看，但收件箱不承诺「会自己发现」，还是请你登好后回来点「我登好了」。负责人登录试跑核对过以后，把证据写准、去掉这个标记。

Workday、飞书招聘、Moka 暂时没有检查方法：它们按公司分站点，检查的网址里要有每家公司自己的路径。

## 六、扫描、私信、找内推人、读消息：原来写给 ego 的脚本照样跑

这些活原来都是一段写给 ego 的脚本（ego 的写法：`taskSpace`「任务空间」、`task.page("p1")`、`page.goto`、`page.click`……）。现在不用改脚本：用专用 Chrome 时，同样的脚本交给 `node bin/browser.mjs -e '<脚本>'` 去跑，用法和 `ego-browser nodejs -e` 一样（代码在 `lib/browser-compat.mjs`）。

- **任务空间就是一个窗口。** 第一页在后台开一个新窗口（不抢焦点），之后的页在同一个窗口里开新标签。空间记在 `state/browser-spaces.json`：编号、名字、归谁、每个页面标签（p1、p2……）对应哪个标签页，所以隔一轮脚本还能找回同一页。
- **交给你以后就是你的。** 脚本把空间交给你（handOff）以后，系统要再动它，必须先说「我接管了」（takeOverTaskSpace）；没接管就动，会报「is under user control」停下来，和 ego 一样。
- **本机 AI 也这样跑。** 交给本机 AI（Codex / Claude Code）的提示词按实际用的浏览器写（`lib/prompt.mjs` 的 `{{BROWSER}}` 这几个占位符）：用 ego 时和以前一字不差；用专用 Chrome 时让它跑 `node bin/browser.mjs`，写法说明在 `docs/browser-scripts.md`。Mac 版里本机 AI 在 Codex 的受限沙盒里跑，沙盒里起不了 Chrome（10-03 实测）：它在 `state/browser-host-request.json` 留个请求，工作台每 2 秒看一次，替它把专用 Chrome 开起来（不抢焦点），它等着连上，最多等 30 秒。沙盒要开着网络才连得上本机的调试端口，App 给它开了。
- **说法照 ego。** 点、填默认等 3 秒；点完的回执里带着弹出来的新页（p2、p3……）和页面弹窗（比如「确定要提交吗？」）。弹窗不会被自动点掉，由脚本决定点「确定」还是「取消」。出错一律报 `ego_browser_failed:…`，原来按这个认浏览器出错的地方不用改。

降频和停手写在代码里（`lib/browser-sites.mjs`），不靠脚本自觉：

- **同一个网站同一时间只有一个脚本。** 脚本第一次打开某个网站（比如 zhipin.com）就拿到这个网站的锁，脚本结束才放开。别的脚本要去同一个网站，最多等一分钟，还轮不到就报 `site_busy`，这一轮先不做。
- **碰到验证页就停，来信请你接手。** 打开页面落到验证码、人机检查、「访问过于频繁」这类页面，脚本马上停下，报 `site_check`；这个网站一小时内谁都不再自动打开（登录检查也一样）。验证只由你本人在专用 Chrome 里做；你自己去打开这个网站时，这一小时的等待就清掉，下一轮照常。这个网站是你打开或绑定了的来源（BOSS 直聘、脉脉、小红书、绑定了的 LinkedIn）时，收件箱来一封「<网站> 要你验证」：「打开这个网站」在专用 Chrome 里打开那一页、拉到最前面；「知道了」收起来。同一个网站 24 小时内最多来一封。

LinkedIn 另有一条（负责人 10-02）：**没绑定就自动关着。**「绑定」指登录检查认定你在专用 Chrome（还在用 ego 的，就是 ego）里登好了 LinkedIn；只点了「我登好了」、检查没能核对的不算。没绑定时，自动扫描、找内推人都不碰 LinkedIn，也不算被挡住、不来信催你登录；绑定以后照设置里的开关，你关掉就一直关着。私信不受这一条管，每一条都要你批准。BOSS 直聘、脉脉照旧默认关，你自己打开才做。

## 七、用哪个浏览器

设置 → 账号与连接 最上面一行「浏览器」：专用 Chrome（默认）；装了 ego 才有「改用 ego」。它写的是 `config/pipeline.json` 的 `browser`：`"chrome"` 是专用 Chrome，`"ego"` 是 ego。没写时：

- Mac 版 App 里一律用专用 Chrome；
- 命令行装的，装了 ego 就照旧用 ego，没装用专用 Chrome。

扫描、私信、找内推人、读消息、预填、本机 AI 交办的网页活，现在都能在专用 Chrome 上做；ego 只在你选了它时才用。

## 八、出了问题看哪里

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 「这台电脑上没找到 Google Chrome」 | 没装 Chrome | 装上 Chrome 后再点一次 |
| 「专用 Chrome 已经开着，但连不上」 | 专用档案被一个连不上的 Chrome 占着（卡住了，或者有人不带调试端口直接用这份档案开了 Chrome） | 把专用 Chrome 完全退出（⌘Q）后再试 |
| 登录检查一直「看不出来」 | 这个网站登录后的样子和检查方法对不上 | 点「我登好了」继续；把网站记下来，修 `config/accounts.json` 里的 probe |
| 登录检查说「网站要先验证」，或者扫描报 `site_check` | 网站拦下了程序的访问 | 在专用 Chrome 里打开那个网站，自己完成验证；一小时内系统不会再去敲它 |
| 本机 AI 报 `chrome_host_wait` | 它在沙盒里，请工作台打开专用 Chrome，30 秒没等到 | 看 OfferCrew 开着没有；运行日志里有「本机 AI 要用专用 Chrome，没打开」就照那一句处理 |
| 扫描报 `site_busy` | 同一个网站上有别的脚本在跑，等了一分钟还没轮到 | 不用管，下一轮会再做 |

代码在 `lib/browser-host.mjs`（主机）、`lib/cdp.mjs`（和 Chrome 说话的那一小段）、`lib/login-probe.mjs`（登录检查）、`lib/browser-compat.mjs` 和 `bin/browser.mjs`（照 ego 的写法跑脚本）、`lib/browser-sites.mjs`（网站排队、碰到验证页停手）、`lib/ego-browser.mjs`（入口：选浏览器、打开登录页、跑脚本）。
