# LinkedIn 网页收信

专用 Chrome 登录 LinkedIn 后，后台在 09:00–21:00 每 10 分钟检查消息。自动开关为 `pipeline.linkedin_chat_watch`，缺省开启；关闭或暂停 Watcher 不影响本人手动检查。打开线程可能被 LinkedIn 标记为已读；程序不填写或发送消息，不需要邮箱或模型。

自动检查只复用正在运行的专用 Chrome，整轮在同一个隐藏页读取，不建可见窗口、不激活浏览器；本人关闭 Chrome 后不会自动把它拉起。Chrome 不支持隐藏页时直接报告失败，不回退成可见窗口。连续读取失败按 20、40、最多 60 分钟退避，安全验证至少等 60 分钟，成功读取后恢复正常间隔。退避保存在检查状态中，重启不会清零；本人仍可手动检查。没有新来信不产生手机提醒。

设置账号页和收件箱提供手动检查、最近结果及任务入口。`GET /api/linkedin-inbox` 返回实际检查状态；`POST` 同一路径 `{action:"check"}` 进入既有操作队列。可显式附 `thread_url` 与 `record_id`，两者不能唯一对上时不会强行写入。登录失效、安全验证、读取失败、部分读取、没有新消息分别反馈；夜间只暂停自动检查。

消息以网页提供的 message URN 去重，保留完整正文、发送者、方向、线程及页面时间原文。没有机器可读时间时 `sent_at` 留空，`observed_at` 仅表示本机何时读到。优先用已有线程关联原岗位，再用唯一个人主页或唯一姓名；群聊和歧义关联不猜、不新建岗位。确定收到的来信进入原岗位的回复待办；来源不明的合为一项待关联提醒。

首次检查也查看已经打开的线程，只提示其中最近一条尚未登记的来信，旧历史仅存档。以后按消息 ID 检查，不会因最后一句是本人发出而丢掉之前的新来信。网页与通知邮件只有在线程、发送者、正文开头和时间范围均匹配时才补全同一事件；不会把同一线程的所有消息合为一条。网页消息本身不伪装成邮件或发送回执。

后续补加载的消息若排在已知来信之前，只存档，不覆盖较新的回复。相同 URN 的正文后来完整显示时，只在原文开头、发送者、方向与线程一致时补全，不生成另一条来信。若旧版本曾把历史消息显示为当前回复，再次读取同一线程会按页面顺序恢复已存的最新来信；原始事件、时间、已处理状态和待办身份保留，不重新提醒。正文变化会更新确认版本，之前打开的旧正文不能继续作为确认依据。

每轮最多读 12 个线程，已知线程和网页列表轮换；未加载的更早历史不宣称完整同步。完整可见来信保存在 `state/linkedin-browser-messages.ndjson`，待办事件在 `state/inbox-events.ndjson`，最近检查在 `state/linkedin-browser-inbox.json`。自动检查只留定时运行账和状态，不新增普通用户任务卡；手动检查沿用任务卡。尚不支持附件文件下载、群聊自动归属或代替本人回复。
