# 客户端结构

OfferCrew 使用一份 Node.js 引擎和数据模型。`bin/serve.mjs` 装配本机 HTTP 接口、原生网页、后台周期和业务模块；`desktop/main.mjs` 提供 Electron 生命周期、窗口、菜单与桌面集成。公开快照不切换成另一套 Basic 功能树。

| 路径 | 职责 |
| --- | --- |
| `lib/`、`bin/` | 岗位发现和判断、材料、联系人、消息、任务、动作确认、回执、模型与浏览器客户端 |
| `web/` | 本机工作台及经加密网关交付的手机页面 |
| `desktop/` | Electron 外壳；开发构建使用同一引擎 |
| `config/`、`candidate/` | 共享默认规则、提示词和虚构资料模板 |
| `skills/`、`docs/` | 本机执行器所读的技能、运行规则和参考文档 |
| `relay/phone/public/`、`relay/phone/vendor/` | 手机浏览器客户端与其第三方解码器，目录名不代表携带中转服务实现 |

数据由 `RADAR_ROOT` 选择。桌面使用独立数据目录，`bin/data-root.mjs` 将只读代码和模板挂进去；个人配置与数据保留为本机文件。任务和动作的主要账本在 SQLite 中，其他记录仍有 JSON/NDJSON。确认绑定具体内容版本，外部结果写入回执；无法确认的结果不能冒充成功。

桌面和手机操作使用同一套本机 API。手机连接官方中转；客户端负责配对与端到端加密。模型调用、邮箱与招聘平台是另外的网络边界。模型或网页内容作为外部数据处理，不替用户作出外发授权。

自带 Key、受支持本机运行时和官方补给集中经 `backends`、`model`、`chat`、`text-conf` 等模块接入同一业务层。模型选择会影响能力和费用，不更换业务状态机。

本快照物理排除商业服务端 Worker、部署配置、管理员工具、签名/上传流程、开发实测资料、个人数据和私有 Git 历史。`CLIENT-MANIFEST.json` 按文件列出本次客户端的内容哈希与用途；依赖通过 npm 锁文件固定。动态 ATS 加载及手机路由别名也纳入导出闭包检查。
